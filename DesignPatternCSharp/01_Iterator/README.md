# Iterator

## どのようなものなのか
数え上げができるもの（以降、集合体）に対してその数え方を提供するパターン
数え上げるロジックをIteratorに切り離すことで、再利用性を高める。
集合体はIteratorのインターフェースに対して実装することで、Iteratorを切り替えるだけで、数え上げの方法を切り替えることができる
つまり、内部の数え上げる部分の実装を変更しなくてよい。

## 用途
数え上げるやり方が複数あるような場合に使えると考える。

## サンプルコードの説明
ユーザの一覧に対して以下のように数え上げるiteratorを実装する
- 単純に数え上げる
- 特定の性別だけ数え上げる

## 所感
Iteratorの責務は数え上げる部分だけ。
この部分だけを責務にするという考え方が面白いなと思った。（なかなか思いつかない。）

Iteratorをnewする部分は最終的にはFactoryクラスに追い出すようになりそう。
そうじゃないと、結局newするクラスが変わるので、集合体の具象クラスの中身をいじる必要がある。

C#ならIteratorのインターフェースはすでに`IEnumerable<T>`があり、これを実装すればforeachで回せるので、自分でIteratorパターンを一から実装するのはなさそう。

特定の性別だけを数え上げるIteratorは特定の性別だけを持つ集合体を先に作っておけば不要となる。
数え上げるだけでなく、抽出するという責任もこのクラスに持たせるべきか、悩ましいところ。
↓
特定の性別だけを持つような場合、AggregatorがそもそもUser専用になってしまう。
AggregatorというのはUser専用ではなくもっと抽象化したもの
条件を指定してあげて、それだけを数え上げるようなIteratorがあれば良さそう。
